# CLAUDE.md 制作指引（通用工作流）

> **这是什么**：`cc-agent-setup` skill 子功能的工作流指引（权威版）——为任意类型的项目生成量身定制的 CLAUDE.md。
> **核心思想**：只定义**工作流**（流程怎么走、骨架长什么样），不预设任何领域的规范内容——规范内容由 Claude 按项目类型现场调研、讲解、经用户选择后生成。
> **配套示例**：本 skill 文件夹 templates/ 下有两份成品——CLAUDE-software.md（软件开发类）、CLAUDE-skill.md（agent skill 工作区类），仅供参照格式与机制。
> **怎么用**：在目标项目对话中触发 `/cc-agent-setup` 并说明要生成 CLAUDE.md，Agent 读取本文件按五步执行。

## 执行总则

1. 全程中文沟通；讲解用比喻、少术语，照顾非计算机专业用户
2. 严格按五步顺序：识别类型 → 讲解 → 选择 → 生成 → 交付；禁止跳过讲解直接生成
3. 本指引只产出 CLAUDE.md 一个文件；不初始化项目、不装依赖、不建目录（用户随即要求初始化时，交回 `cc-agent-setup` 主功能 A 流程）
4. 优先级：用户的明确答案 > 附录A 用户全局默认 > 领域通用惯例
5. 涉及联网、安装等操作先向用户确认
6. **奥卡姆剃刀 / 按需生成**：生成的 CLAUDE.md 及其【一次性】初始化指令只应创建当前必要的文件/目录，不预建空目录；`.env.example`、`.gitignore` 等按项目实际类型与需求生成，禁止一上来就复制通用大全

## 第一步：识别项目类型与惯例调研

1. 若用户未说明，先问：项目类型 + 一句话目标
2. **调研该类型的结构惯例**（「第零问」的推广）：这个领域公认的项目组织方式是什么？
   - 依据优先级：用户提供的参考项目/仓库 > 领域权威惯例（可联网查证）> 通用常识
   - 例：软件跟框架目录结构；学术研究按文献/数据/代码/写作分区；agent skill 按 SKILL.md 规范组织；MCP 按服务端实现/工具定义/测试组织
3. 记录调研结论供后续使用；调研不到就如实说明，按通用结构兜底

## 第二步：讲解（用十维清单挑出适用方面）

- 对照**附录B 十维清单**逐维判断该项目是否适用
- 适用的维度逐项向用户讲解：每项 2~4 句 + 一个比喻；**举例必须用该项目类型的语言**（对研究项目讲文献版本和数据溯源，不是讲 npm）
- 讲解时可引用 `cc-agent-setup` skill 的 `templates/` 中类型最接近的成品模板作对照案例
- 不适用的维度明确说出「跳过及原因」，给用户否决的机会
- 清单之外、该类型特有的管理方面也应补充——清单保底，不设上限

## 第三步：选择（逐项拍板）

- 用 AskUserQuestion 提问：每轮 ≤4 题；每题 2~4 个选项；推荐项放第一个并标（推荐）
- 待拍板项超过 4 个时分轮提问，每轮凑满 4 题，减少来回
- 每题尽量给出「默认」值：来自附录A（用户全局默认）或第一步调研到的领域惯例；两者皆无则不标默认
- 接受选项外的自定义方案，**答案原样落实（用其原始表述），禁止套用相近选项替代**；用户答「不确定」→ 采用默认并明确告知

## 第四步：生成（通用骨架 + 按选择填充）

无论什么类型，CLAUDE.md 遵循同一骨架——**机制固定，内容随类型变化**：

```
# CLAUDE.md
> 模板使用说明（由 `cc-agent-setup` skill 提供：空目录触发 `/cc-agent-setup` 自动复制并初始化；
  亦可手动复制 → 说「按 CLAUDE.md 初始化项目」→ 执行【一次性】章节后自动删除它并填写产物说明）

## 项目简介
（名称 / 一句话目标 / 项目类型：初始化时填写）

## <维度规范章节> ×N
（第二步选定的每个管理维度一节，标题按类型措辞；
 附录A 中适用的全局默认并入对应章节；
 目录结构类章节的树只画形状、不逐文件注释——解释统一放「项目产物说明」）

## 章节维护
（固定原文：【一次性】章节执行后删除并写入「项目产物说明」；
 常驻规范默认保留；规范与现实矛盾时停下提示用户裁决）

## 流程归属（可选——项目有配套流程 skill 才设）
（两三行声明：哪些流程归哪个专业流程型 skill；
 流程与本规范冲突时以本规范为准。无配套 skill 则不设本节——
 日常工作习惯不写入 CLAUDE.md，流程归 skill 管）

---

## 【一次性】新项目初始化指令
（编号步骤：本类型项目从零到可用需要生成/安装/配置的全部事项，
 按第一步调研的惯例写；固定收尾两步：删除本章节、填写「项目产物说明」）

## 项目产物说明
（占位：初始化完成后由 Agent 填写——生成了哪些文件/目录、各自用途）
```

篇幅要求：≤150 行、一屏可扫读、宁短勿长——**不设下限**，行数不是质量指标，只保留规则本身；未来才生效的规范（待引入的工具、计划中的脚本）登记目标项目 `TODO.md`，不写入 CLAUDE.md。生成后通读，清理因取舍而失效的交叉引用。
用途为「可复用模板」时：剥离项目专属信息（换回占位符），交由 `cc-agent-setup` skill 登记模板索引。

## 第五步：交付与自检

1. **自检并逐条报告**：所选各维度的选项值均已落实；附录A 适用项已并入；骨架机制（模板说明/章节维护/一次性章节/产物说明）齐全；篇幅达标（行数验证：≤150 行）；无与用户全局 CLAUDE.md 重复的条目、无未来才生效的条目、无同一信息写两遍（如目录树注释与产物说明）；**一次性初始化指令未过度生成（不预建空目录、.env.example 与 .gitignore 按需生成）**
2. **向用户说明三件事**：初始化触发词（在项目目录触发 `/cc-agent-setup`；手动场景说「按 CLAUDE.md 初始化项目」）；【一次性】章节自动删除机制；规范与现实矛盾时 Claude 会停下提示裁决
3. **到此为止**：不执行初始化、不做任何额外文件操作（用户随即要求初始化时，交回主功能 A）

## 附录A：用户全局默认（跨类型个人约定，默认并入每个生成的 CLAUDE.md）

**并入规则**：生成前先读用户真实全局 CLAUDE.md（`~/.claude/CLAUDE.md`），其中已有的约定**不再并入**项目文件——全局规则留在全局，避免每个项目挂一份副本、改一次同步 N 处；仅当附录A 比全局文件更具体且项目确实需要时才并入细化条目。

- 与 Claude 沟通、代码注释、TODO、计划文档：中文
- 标识符、文件名、目录名、分支名：英文，禁止中文路径
- 依赖分级规则 + 用户级安装三步流程：项目库一律装项目级；用户级仅限多项目共用且版本不敏感、或社区公认用户级的工具，且必须「装前醒目声明 → 凭证存 `D:\BaiduSyncdisk\software`（无独立安装包则导出来源 URL/命令/版本的引导文档；**只在真正保存安装包时询问是否使用默认路径**）→ 装后醒目总结」——适用于一切有依赖的项目类型
- 领域/框架惯例优先于通用规则（第零问）
- 章节生命周期：【一次性】章节执行后删除并填写「项目产物说明」；常驻规范默认保留；规范与现实矛盾时停下提示用户裁决，不得静默违背或擅改
- 危险操作（删除/覆盖/安装/联网）先向用户确认，完成后如实报告
