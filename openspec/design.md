# 日常录音分析工具设计文档

## 1. 项目概述

构建一个**本地运行的日常录音分析工具**，帮助用户通过分析自己的日常录音（会议、演讲、对话等）发现表达问题，并获得具体、可执行的改进建议。

核心能力：
- 自动监控文件夹，放入录音后自动生成分析报告
- 多人对话场景中识别用户本人的声音，只分析用户的语音
- 词句级分析，指出具体问题发生的时间点
- 中英混合录音支持
- 声纹注册 + 纠偏机制，越用越准
- 长录音（1-2 小时）自动按自然停顿切分处理
- 发音标准/正音检测（普通话声调/咬字、英语音素）

## 2. 目标与非目标

### 目标
- 支持常见音频格式：WAV、MP3、M4A
- 音频预处理：VAD 去静音、降噪、按自然间断点切分
- 说话人分离与声纹匹配
- 语音转写（中英混合）
- 多维度分析：填充词、重复词、语速/停顿、情感/语气、发音清晰度、发音标准/正音、表达结构
- 生成 Markdown + JSON 双格式报告
- 保留历史报告，便于后续趋势分析

### 非目标
- 实时录音采集（首期不做）
- 用户账户/多租户服务
- 云端处理或数据上传
- 替代专业演讲教练
- 首期不实现趋势 Dashboard

## 4. 模块职责

### 4.1 文件夹监控器（watcher）
- 使用 `watchdog` 监控 `input/` 目录
- 检测新增音频文件，触发分析流水线
- 记录处理状态，避免重复处理

### 4.2 音频预处理（preprocessor）
- **VAD（Voice Activity Detection）**：检测有语音的区间，去除长时间静音和背景无声段
- **降噪**：使用轻量级降噪算法（如 RNNoise 或谱减法）降低背景杂音
- **切分**：按自然不说话的间断点切分，保证每段在合理处理大小（30 秒 - 5 分钟）

### 4.3 声纹注册（enrollment）
- 用户提供 30-60 秒纯本人语音
- 提取声纹特征向量并保存到本地 `voiceprint/` 目录
- 支持增量更新：用户确认/否认低置信度片段后，用新样本更新声纹

### 4.4 说话人分离与匹配（diarization + identification）
- 使用说话人分离模型将录音按说话人切分
- 计算每段声纹与注册用户声纹的相似度
- 只保留属于用户的片段，过滤其他说话人
- 低置信度片段在报告中标记，供用户校正

### 4.5 ASR 转写（transcription）
- **优先使用统一的 Model API Gateway** 调用外部 ASR 服务，输出带时间戳的词/句级别结果
- API 不可用时自动回退到本地 `faster-whisper` 模型；本地模型也未加载时返回占位结果，保证流水线不中断
- 支持中英混合识别

### 4.6 文本分析（text analysis）
- 填充词检测：嗯、啊、然后、就是、那个、so、like、you know 等
- 重复词/短语检测
- 句子长度分析：过长句子提示拆分
- 逻辑连接词使用分析

### 4.7 音频特征分析（audio features）
- 语速：每分钟字数/词数
- 停顿：过长停顿、频繁短停顿
- 音量/能量变化：忽大忽小、能量分布
- 发音清晰度：基于频谱特征和语音可懂度指标
- 发音标准/正音：结合 ASR 置信度、音素对齐和参考发音，标记疑似不标准读音（如普通话声调偏差、英语音素错误）

### 4.8 情感/语气分析（emotion）
- 使用 emotion2vec 等本地模型
- 识别情绪类别（中性、积极、紧张、疲惫等）
- 检测语气单调、情绪起伏不足等问题

### 4.9 报告生成器（reporter）
- 输出 Markdown 报告：摘要、各维度评分、具体问题、时间戳、改进建议
- 输出 JSON 报告：结构化数据，便于后续趋势分析
- 报告名与录音文件名对应

## 5. 数据流

1. 用户将 `recording.mp3` 放入 `input/`
2. watcher 触发，preprocessor 进行 VAD/降噪/切分
3. diarization 分离说话人，与用户声纹匹配
4. 只保留用户片段，送入 ASR 转写
5. 转写结果 + 音频特征 + 情感分析并行处理
6. 汇总各维度发现，生成报告到 `output/recording_report.md`
7. 低置信度说话人片段在报告中列出，用户可校正

## 7. 技术栈

- **语言**：Python 3.10+
- **ASR**：优先通过统一的 Model API Gateway 调用外部 ASR；API 不可用时回退到 faster-whisper 本地模型
- **声纹/说话人分离**：优先通过 Model API Gateway 获取声纹嵌入；API 不可用时回退到 pyannote.audio / speechbrain / MFCC 本地特征
- **音频处理**：librosa, pydub, webrtcvad 或 silero-vad
- **情感分析**：emotion2vec / transformers
- **发音/音素分析**：phonemizer / 拼音库（如 pypinyin）+ ASR 置信度
- **文件夹监控**：watchdog
- **报告输出**：Markdown + JSON
- **CLI**：Click 或 argparse

## 8. 关键配置项

```yaml
input_dir: "./input"
output_dir: "./output"
voiceprint_dir: "./voiceprint"
audio_formats: [".mp3", ".wav", ".m4a", ".flac"]

vad:
  min_speech_duration_ms: 250
  max_silence_duration_ms: 1000

segmentation:
  max_segment_duration_sec: 300
  min_segment_duration_sec: 10

speaker:
  enrollment_duration_sec: 45
  similarity_threshold: 0.75
  low_confidence_threshold: 0.55

asr:
  model: "large-v3"
  language: "zh"  # 中英混合时 whisper 自动识别

# 统一的 Model API Gateway（默认未启用，启用后优先于本地模型）
api:
  enabled: false
  base_url: "https://your-gateway.example.com"
  api_key_env: "MODEL_API_KEY"
  timeout: 60
  endpoints:
    asr: "/asr"
    embed: "/embed"

analysis:
  filler_words:
    zh: ["嗯", "啊", "然后", "就是", "那个", "这个", "对吧"]
    en: ["um", "uh", "like", "you know", "so", "actually"]
  max_sentence_words: 45
  pronunciation:
    # 低于该置信度的词/字会被标记为“可能发音不标准”
    low_confidence_threshold: 0.65
    # 是否启用音素级正音提示（首期对英语较有效）
    phoneme_check: true
```

## 9. 报告示例（摘要）

```markdown
# 录音分析报告：recording_20260808.mp3

## 总体摘要
- 时长：32 分 15 秒
- 识别到的用户语音：18 分 42 秒
- 主要问题：填充词偏多、部分句子过长

## 详细发现

### 填充词
- 03:12 - 03:18：连续使用 3 次“然后”，建议替换为停顿或具体连接。
- 07:45：使用“嗯”作为开头，可练习直接切入主题。

### 语速
- 平均语速：168 字/分钟
- 05:20 - 05:50 语速偏快（210 字/分钟），建议放慢。

### 情感/语气
- 整体偏中性，12:10 - 12:40 出现语气下降，可能显得疲惫。

### 发音清晰度
- 整体良好，08:30 附近音量较低，部分字不够清晰。

### 发音标准 / 正音
- 05:12 “项目”的“项”疑似读成了轻声，建议确认声调。
- 11:08 英语单词 “specific” 音素 /ɪ/ 位置可能读错，建议对照标准发音练习。
- 18:33 “策略”发音置信度较低，可重录练习。

## 改进建议
1. 每天练习 5 分钟“去填充词”朗读。
2. 将长句拆成 2-3 个短句。
3. 在重要观点前刻意停顿 1 秒。
```

## 10. 声纹纠偏流程

1. 系统对低置信度片段标记 `[?]`
2. 用户在报告中选择“这是我”或“这不是我”
3. 确认后，系统将片段特征加入声纹库（正面样本）或排除（负面样本）
4. 重新计算用户声纹中心，提高下次识别准确率

## 11. 错误处理

- 音频文件损坏：记录错误，跳过并通知用户
- 模型加载失败：给出明确提示，建议检查模型路径或硬件
- 无语音 detected：报告为空，提示用户检查录音质量
- 声纹未注册：提示用户先执行注册流程
